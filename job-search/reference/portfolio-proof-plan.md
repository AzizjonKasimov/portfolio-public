# Portfolio Proof Plan

Many of Azizjon's strongest work examples are private employer work. The goal is to prove
capability without exposing private data, code, credentials, customer details, or employer secrets.

## What To Build

Create public-facing proof in three layers:

1. **Anonymized case studies**
   - Problem, constraints, architecture, technical decisions, and measured impact.
   - No private customer data, internal URLs, raw screenshots, secrets, or proprietary code.

2. **Sanitized technical diagrams**
   - Architecture diagrams for LLM search, AWS data pipelines, LangGraph agents, model evaluation,
     and MLOps monitoring.
   - Use generic service names and synthetic examples.

3. **Small public demos or replicas**
   - Minimal toy versions that show the same engineering pattern on public or synthetic data.
   - Example: semantic-search demo, queue-worker pipeline demo, evaluation dashboard, or LangGraph
     data-processing agent.

## Safety Rules

- Use synthetic data in screenshots and demos.
- Do not publish employer code, database schemas, customer data, logs, raw exports, credentials,
  internal dashboards, or internal URLs.
- If a metric is already in the resume/context, keep it consistent. If a metric is uncertain, mark
  it as approximate or leave it out.
- Prefer architecture and reasoning over proof that requires revealing private implementation
  details.
